# 07 · 开发约定

本文汇总本项目的惯用写法，新增功能时请尽量遵循，以减少风格分裂。

## 1. 配置：`AppConfig` 模式

`AppConfig`（`AppConfig.kt`）是全局配置单例（`object`），所有用户可调设置都放这里。

### 新增一个设置项的完整步骤

以新增 `示例开关` 为例：

1. **字段**（用 Compose 可观察状态）：
```kotlin
var exampleEnabled by mutableStateOf(false)
```
2. **KEY 常量**（`object KEY` 内）：
```kotlin
const val EXAMPLE_ENABLED = "example_enabled"
```
3. **`load()`** 读取：
```kotlin
exampleEnabled = kvault.getBoolean(KEY.EXAMPLE_ENABLED) ?: false
```
4. **`save()`** 写入：
```kotlin
kvault.putBoolean(KEY.EXAMPLE_ENABLED, exampleEnabled)
```
5. **设置页**加 UI（两套风格都要加）：`MiuxSettingScreen.kt` 与 `Material3SettingScreen.kt`，修改后调用 `AppConfig.save()`。

常用类型：`mutableStateOf`（Boolean/对象）、`mutableIntStateOf`（Int）、`mutableStateListOf`、`mutableStateMapOf`。

> 注意：`AppConfig.save()` 末尾会调用 `reloadWidgetTimelines()`，即任何配置改动都会刷新桌面小组件。若不需要，可评估是否要放到更合适的位置。

## 2. ViewModel 约定

- 均继承 `androidx.lifecycle.ViewModel`。
- 统一 **Factory 模式**：
```kotlin
class XxxViewModel : ViewModel() {
    var data by mutableStateOf(...)
    companion object {
        val Factory = viewModelFactory { initializer { XxxViewModel() } }
    }
}
```
- 页面获取：`viewModel(factory = XxxViewModel.Factory)`。
- 跨页面共享：`AppViewModel` 通过 `LocalAppViewModel.current` 取用。
- **状态用 Compose 状态类型**（`mutableStateOf` 等），不用 `StateFlow`。
- **不使用 `viewModelScope`**；网络请求在页面的 `LaunchedEffect` 或 `rememberCoroutineScope().launch` 中发起。

## 3. 网络调用约定

- 客户端是 `object` 单例：`QZClient` / `SunshineClient`。
- 页面里直接调用：
```kotlin
LaunchedEffect(termId) {
    val result = QZClient.getExamScores(termId)
    result?.let { viewModel.scoreListMap[termId] = it }
}
```
- 解析结果为空时通常不覆盖已有数据。
- 缓存的读写集中在对应 ViewModel（如 `ScoreViewModel.loadScoreCache()`）。

## 4. expect / actual 平台抽象

当"各平台实现不同"时：

1. `commonMain` 声明 `expect`（函数或 object）。
2. `androidMain` / `iosMain` 分别提供 `actual`。
3. 典型范例见 `WidgetDataStore`、`KVaultUtils`、`Platform`。

新增时建议放在 `utils/` 下并保持 `commonMain` 接口简洁。

## 5. 双 UI 风格约定

- 每个功能尽量两套都实现：`screens/miuix/` 与 `screens/material3/`。
- 组件映射：

| 能力 | Miuix | Material 3 |
|---|---|---|
| 顶栏 | `SmallTopAppBar` | `TopAppBar` |
| 弹窗 | `WindowDialog` | `AlertDialog` |
| 底部弹窗 | `WindowBottomSheet` | `ModalBottomSheet` |
| 列表项 | `BasicComponent` / `*Preference` | `M3Row` |
| 分组 | `SmallTitle` + `Card` | `M3GroupHeader` + `M3GroupSection` |
| 加载 | `InfiniteProgressIndicator` | `CircularProgressIndicator` |
| 下拉 | `PullToRefresh` | 顶部刷新按钮 |
| 触感 | 视情况 | 普遍使用 `hapticFeedback` |

- 公共逻辑抽到 `components/ScheduleShared.kt`、`components/DatePickerShared.kt` 之类，避免两套重复。

### 跨主题复用 Miuix 组件的注意点
`App.kt` 的 Material3 分支**没有包 `MiuixTheme`**。若在 M3 页面使用 Miuix 组件（如 `NumberPicker`），其默认 `colors` / `textStyle` 会读取 `MiuixTheme`，应**显式传参**（如用 `MaterialTheme.colorScheme`、`MaterialTheme.typography`）避免依赖缺失的主题。

## 6. 资源约定

- 静态资源（图片、字体、JSON、拼音词库）放 `shared/src/commonMain/composeResources/`。
- 读取用 `utils/ResourceUtils.kt`（`readText` / `readBytes`）。
- 本地缓存文件用 `utils/FileStoreUtils.kt`，文件名常量放 `constants/FileName.kt`。
- 敏感/用户配置用 `utils/KVaultUtils.kt`。

## 7. 序列化约定

- 需要持久化的模型加 `@Serializable`。
- 用 `utils/JsonUtil.kt` 的 `toJson` / `parseJson`，不要直接 new `Json`。

## 8. 导航约定

- 新页面：在 `Route.kt` 加路由 → 在 `App.kt` 两个分支各加一个 `entry<Route.X>` → 用 `navigator.push(Route.X)` 跳转。
- 需要返回结果：`navigator.navigateForResult(...)` + `setResult(...)` + `observeResult(...)`。
- 首页内的子页（Today/Schedule/Function）不是路由，扩展时改 `HomeScreen` 的 Pager。

## 9. 命名约定（观察所得）

- Material3 页面统一 `Material3` 前缀；Miuix 页面部分带 `Miuix` 前缀（如 `MiuixExamScreen`），部分不带（如 `ScheduleScreen`、`TodayScreen`）。
- 评分/视图模型按功能命名（`ScoreViewModel`、`ExamViewModel`、`PlanViewModel`）。
